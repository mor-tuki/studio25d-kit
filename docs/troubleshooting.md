# トラブルシューティング

作者が実際の配信・LT の準備で踏んだ落とし穴と、その直し方です。上の 2 つは「確かめ方」の話で、いちばん大事です。

---

## 1. 画面の端に黒い帯が出る（のに、確認では気づかなかった）

**症状**：カメラが動くと、画面の右端などに細い黒い帯（＝絵の外）が一瞬出る。0.25 秒おきのコマを縮小して並べたシートで目視したときは「問題なし」に見えた。あとで全コマの端を数えたら、11 本中 8 本のムーブで出ていた。

**原因**：暗い絵の黒い帯は、縮小すると背景に溶けて見えない。目視は「無い」ことの証明にならない。

**直し方**：
- 絵の外は **数で測る**：`python tools/studio_check.py coverage --serve`（背景だけを白、外をマゼンタで描いて画素を数える）。合格は `max=0px`。
- 配信画面で `G` を押すと絵の外がマゼンタで見え、`H` の HUD に 2 秒ごとの画素数が出る。
- 報告するときは、その確認が「数」なのか「縮小した画像を見ただけ」なのかを書き分ける。

## 2. 黒を消したら、別の失敗（縞）が合格してしまった

**症状**：黒い帯を消すために絵の端を引き伸ばしたら、端の明るさのチェックは合格したが、右端に引き伸ばしの縞がはっきり出た。

**原因**：「黒い画素」を測っていた。検出したかったのは「絵の外が映ること」なのに、見た目の症状（黒）を測っていたので、症状が黒以外に化けると素通りした。

**直し方**：**検出したい失敗そのものを印にして測る**。このキットの coverage は「絵の外」をマゼンタで塗って数えるので、黒でも縞でも引き伸ばしでも、絵の外なら必ず数に出る。さらに、クランプを外してわざと外を映す陰性対照が `alive: True`（検出器が生きている）であることも合格条件にしている。絵の端を引き伸ばす（パディング）は禁止（engine.js の格子は UV 0〜1 の外に頂点を作らない）。

## 3. 部屋の種類や大きさを変えたら、カメラがキャラを見失う

**症状**：小さな部屋で調整した動き（「見上げるとき注視点を目印へ 18% 寄せる」）が、目印が数十 m 先にある大きな部屋では注視点を 10 m も飛ばし、キャラが画面から消えた。

**原因**：**割合で書いた定数は、部屋の大きさが変わると別の値に化ける**。半径 7 m の部屋の 18% と、54 m 先の目印の 18% は別物。

**直し方**：割合で動かす量には **絶対値の上限** を付ける（engine.js の注視点の寄せは水平 0.6 m で頭打ち）。新しい種類・大きさの部屋を足したら、既存の割合系の定数（寄せ・押し出し・半径比 `maxRadiusRatio`）を一度ぜんぶ疑い、`shots` と `smoke` を撮り直す。静止画は「時間を飛ばした評価」なので、なめらかに追う動き（追従）の向きの判定は通しの録画で見る。

## 4. AI エージェントに起動させたサーバーが、いつの間にか止まっている

**症状**：サブエージェント（や別のターミナル）にスタジオの起動まで任せたら、そのエージェントが終わった瞬間にスタジオがつながらなくなった。

**原因**：サーバーがそのシェルの **子プロセス** だった。親のシェルが終わると一緒に終了する。依頼文に「起動したまま終わってよい」と書いても止まる。

**直し方**：
- 常駐させたいサーバーは、親から切り離して起動する：Windows は `start-studio.ps1`（`Start-Process -WindowStyle Hidden`・PID は `output/server.pid`）、macOS / Linux は `start-studio.sh`（`nohup … &`）。
- エージェントに頼むときは「起動確認だけして止めてよい・常駐は人（または親のエージェント）がやる」と書く。`tools/studio_check.py` は自分で起動したサーバーを最後に必ず止める設計。
- 止める：Windows `Stop-Process -Id (Get-Content output\server.pid)`／mac・Linux `kill "$(cat output/server.pid)"`。

## 5. VRM 1.0 のキャラが後ろを向く・腕が上がったまま

**症状**：VRM 1.0 のモデルを入れたら、背中がカメラ側を向き、腕が上がったままだった（VRM 0.x のモデルでは正常）。

**原因**：three-vrm は VRM 0.x だけを 180° 回す（`VRMUtils.rotateVRM0`）。VRM 1.0 は逆を向いたまま読まれ、正規化ボーンの回転の符号（x・z）も逆になる。スタジオの姿勢コード（腕を下ろす角度・歩行の脚の振り・体の向き）は VRM 0.x の向きで書かれている。

**直し方**：`studio/js/vrm1_adapt.js` が VRM 1.0 を自動判定して、(1) 中身を内側のグループで 180° 回し、(2) 正規化ボーン → 実ボーンへ移す瞬間だけ回転を Ry(π) で共役（x・z を反転）する。VRM 0.x では何もしない。腕の下ろし角は `studio.config.json` の `character.armsDownZ`（rad・既定 1.15）。別のページ（比較用ページなど）で同じモデルを表示する場合は、そちらにも同じ切り替えが必要。

## 6. キャラの色が、別の照明で違って見える（MToon）

**症状**：MToon シェーダーのモデルにしたら、髪が明るく抜け、顔が白く飛んだ。スタジオの照明に合わせて色を詰めたら、今度は別の照明（比較用のページ）では暗く見えた。

**原因**：MToon の見え方は照明（主光・半球光・環境光 GI・リムライト）に強く依存する。色の調整は「その照明での正解」でしかない。

**直し方**：
- 色は VRM ファイルを書き換えずに、実行時の補正（`studio.config.json` の `character.materialRules`：`tint`・`shadeMul`・`shift`・`hueDeg`）で詰める。作者のモデルでは base／shade／GI（0.15）／rim（0）の調整で落ち着いた。
- **見せる場所（配信で使う部屋）の照明で確かめる**。部屋ごとの光は `rooms.json` の `lighting`。部屋を足したら、キャラの見え方を `shots` で撮り直す。

## そのほか

| 症状 | 確かめること |
|---|---|
| 画面が真っ黒・「読み込みエラー」 | ブラウザの開発者ツールのコンソール。`file://` で開いていないか（必ず `http://127.0.0.1:8811/`）。`rooms.json` の JSON が壊れていないか（`python -m json.tool studio/rooms.json`） |
| 動画スライドが映らない / 止まっている | H.264 の MP4 か（`ffprobe`）。Playwright 同梱の Chromium は H.264 を持たないことがある＝ Google Chrome / Edge / OBS で確認。`P` で再生状態を切り替え |
| 動画の音が出ない | 既定は消音（ブラウザの自動再生の制限のため）。`K` か操作パネルで音ありに。OBS は「OBS で音声を制御する」 |
| スライドが歪む | スライドの縦横比と `screen` 矩形の縦横比を揃える（推奨 16:9） |
| スライドの前に黒い山・突起が出る | 深度の段差がスクリーンの前にはみ出している。`screenClamp` の帯（特に `bottom`）を広げる |
| 360° で床が放射状に流れる | 床の模様が強い／中央に物がある絵。`pano.radius` を小さく、`pano.height` を調整。直らなければ床を単純にして作り直す |
| 360° の継ぎ目が見える | `pano_prep.py --xfade 30` で作り直し、`studio_check.py pano` で ratio を確認 |
| ヘッドレス Chrome がメモリを食う | 検査は Chrome を 1 つだけ起動して必ず閉じる設計（作者の環境で一度 11GB 使った）。空きメモリが `--min-free-gb`（既定 3GB）未満なら起動しない |
| ポートが使用中 | `--port 8812` など別の番号で起動（`start-studio.ps1 -Port 8812`） |
